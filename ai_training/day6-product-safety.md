# День 6. DataSet: безопасность состава продуктов

## Постановка

Задача: по сырому тексту состава продукта подготовить учебную оценку потенциальной безопасности продукта на основе заданного справочника опасных и спорных добавок.

Тип задачи: `extraction + classification + structured generation`.

Модель должна:

- находить в составе добавки и ингредиенты из переданного справочника;
- учитывать разные формы записи: `E250`, `Е-250`, `нитрит натрия`, `sodium nitrite`;
- определять общий уровень риска по найденным совпадениям;
- возвращать ответ в строгом JSON-формате;
- кратко объяснять вывод понятным языком;
- явно показывать уверенность ответа.

## Граница ответственности

Модель не заменяет медицинскую, нутрициологическую или регуляторную экспертизу. Результат нужен для учебного fine-tuning задания и пользовательской навигации по составу.

Модель не должна использовать собственную память как источник истины об опасности добавок. Источник истины — справочник, переданный во входе или подготовленный алгоритмически до вызова модели.

Если в составе нет совпадений со справочником, модель должна вернуть низкий или неизвестный риск и не выдумывать опасные ингредиенты.

## Вход

В каждом примере `user` содержит:

- название продукта, если оно доступно;
- сырой состав продукта;
- справочный контекст по опасным или спорным добавкам, релевантный для этого примера.

Состав может быть грязным: с разными регистрами, языками, пробелами, дефисами, маркетинговыми фразами и неполными формулировками.

## Выход

В каждом примере `assistant` возвращает только JSON без Markdown и свободного текста вокруг.

Ответ должен включать:

- общий уровень риска;
- найденные добавки или ингредиенты из справочника;
- причины предупреждений;
- короткий итог для пользователя;
- уровень уверенности.

Точный контракт ответа зафиксирован в [product-safety-response-schema.json](product-safety-response-schema.json).

Минимальная форма ответа:

```json
{
  "risk_level": "medium",
  "matched_additives": [
    {
      "matched_text": "Е250",
      "canonical_name": "нитрит натрия",
      "code": "E250",
      "risk_level": "high",
      "reason": "Добавка найдена в справочнике как спорная или опасная."
    }
  ],
  "warnings": [
    "Найдены добавки из справочника, требующие внимания."
  ],
  "safe_summary": "Продукт содержит спорные добавки; лучше не считать его повседневно безопасным.",
  "confidence": "high"
}
```

Допустимые значения `risk_level`: `low`, `medium`, `high`, `unknown`.

Допустимые значения `confidence`: `low`, `medium`, `high`.

Если совпадений со справочником нет, `matched_additives` и `warnings` должны быть пустыми массивами.

## Роль алгоритмической части

Эта задача проектируется как гибрид:

1. Алгоритм или предварительная подготовка выбирает релевантные записи справочника.
2. Модель нормализует грязный состав, сопоставляет варианты написания и формирует стабильный структурированный вывод.

Если вход уже полностью структурирован как список кодов добавок, задачу проще решить алгоритмически. Fine-tuning полезен именно для устойчивости к естественному тексту состава и стабильного формата ответа.

## Успех этого этапа

Пункт 1 считается выполненным, когда зафиксированы:

- выбранная задача;
- тип задачи;
- граница ответственности модели;
- форма входа;
- форма выхода;
- роль справочника и алгоритмической подготовки.
